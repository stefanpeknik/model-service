Three request paths

The real test-flow reference expands the immediate and scheduled paths into container topology and sequence diagrams, including HTTP, Ray, SQL, local calls, mounted files, and validation limits.

These are source-level paths. Runtime configuration chooses their concrete origins and adapters. Production wiring.

Low-level inference
  HTTP proxy → Ray model route → model output

Synchronous workflow
  HTTP API → SynchronousWorkflowService → HTTPWorkflowDispatch
  → Ray workflow ingress → WorkflowApplication → workflow → result

Scheduled workflow
  HTTP API → ExecutionScheduler.schedule → provider preparation
  → repository admission → worker claim → HTTPWorkflowDispatch
  → Ray workflow ingress → WorkflowApplication → workflow
  → durable processing settlement → provider finish → public success

The prostate workflow calls SlideHeatmapProcessor, which selects masked tiles and uses RayHeatmapPredictor to call the classifier through a Ray deployment handle. Scheduler-to-workflow dispatch uses HTTP; workflow-to-model prediction uses the handle. Composition; Predictor.
