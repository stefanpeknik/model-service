What should own a scheduled Ray request?

This demo tests the boundary between the durable demand controller and Ray Serve. Push one execution through cold start, queue pressure, cancellation, deadline expiry, and controller loss. The question is whether the first dispatch adapter should use HTTP or a Ray deployment handle.

Working verdict: use HTTP for the first scheduled dispatch adapter. A dead HTTP client asks Serve to cancel its request. A dead handle client left the observed request running. HTTP also keeps the demand controller outside the Ray process boundary. The durable controller still owns admission, deadlines, retries, leases, and attempt fencing because Serve queues are not durable.

What the local probe found
